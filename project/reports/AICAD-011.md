# AICAD-011 — Draft RFC-0005 diagnostics

## Objective
Draft RFC-0005 (diagnostics), covering the Stage-0 build item "diagnostic
schema", per `project/TASKS.yaml` (AICAD-011).

## Dependencies checked
AICAD-010 (RFC-0004) — complete, see `project/reports/AICAD-010.md`. No
owner ruling exists for D10 (diagnostic stability policy) — confirmed by
re-checking `project/OWNER_DECISIONS.md` before writing this RFC.

## What was done

Wrote `rfcs/0005-diagnostics.md`:
1. Froze the diagnostic code taxonomy (§2), JSON schema (§3), and
   suggestion-confidence contract (§4) verbatim from
   `docs/plan/17_CLI_DIAGNOSTICS_SCHEMA.md` §10-12, updating only the
   example file extension from the plan's placeholder `.cadl` to the
   `.aicad` extension frozen in RFC-0001 §3 (no other content change).
2. Carried forward `docs/plan/11_AI_NATIVE_SKILLS_AND_AGENT_PROTOCOL.md`
   §5's structured-diagnostics-for-agents example and its "suggestions
   must be generated by reliable reasoning, never fabricated guesses"
   requirement, stated as a correctness requirement on whatever code
   populates `suggestions`, not a UX nicety.
3. Cross-referenced RFC-0002 §3's kernel-independence contract as it
   applies specifically to diagnostic content (§5): `backend_details` may
   carry OCCT-specific detail, but never as the sole explanation.
4. Froze build/query output schemas and exit-code meanings from `17`
   §13-15.
5. **Explicitly did not resolve D10.** Since no owner ruling exists for the
   diagnostic-code/schema stability policy, §7 states plainly what this
   RFC does *not* answer (renumbering/removal policy pre-1.0, new-family
   approval process, schema field stability) and instructs
   `crates/cad-diagnostics` (Stage 2, AICAD-038) to treat every code/field
   as provisional until D10 is ruled on, rather than letting silence be
   read as an implicit "codes are frozen forever" or "codes are freely
   changeable" policy.
6. §8 records why the RFC was still worth drafting now rather than
   deferred until D10 resolves: the taxonomy/schema/suggestion-contract
   *shape* is not itself in dispute anywhere in the plan, only its
   long-term change-management policy is.

No escalation condition was triggered: this RFC changes no public
syntax/semantics beyond RFC-0001's already-approved `.aicad` extension
substitution in one example, does not weaken any gate/benchmark, respects
the kernel-independence contract, and — critically — does not resolve D10
implicitly; it says exactly what remains open.
