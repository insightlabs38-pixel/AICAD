# Semantic-reference architecture

Stage 4 implements persistent, kernel-neutral topology references without promoting kernel handles or raw enumeration into identity.

## Layer ownership

- `cad-references` owns entity/reference recipes, durability classes, feature anchors, raw-handle epoch semantics, and kernel-neutral reference values.
- `cad-query` owns query clauses/predicates/cardinality, candidate evaluation, fail-closed resolution, health aggregation, diagnostics, and fingerprint evidence/ranking.
- `cad-cli::query_lowering` converts real source `HirItem::Query` declarations into `Query` + `AnyRef`.
- `ParametricBuildSession` supplies current candidates, scope lookup, source-reference registration, query registry, feature/provenance evidence, lineage evidence, and rebuild/replay context.
- the OCCT adapter supplies exact topology and operation-local lineage below the kernel-neutral boundary.

## Identity versus evidence

Durable semantic identity belongs to AICAD. Kernel lineage (`Generated`, `Modified`, deletion), geometric properties, and fingerprints are evidence used to evaluate a recipe.

Raw shape handles and raw face/edge indices are build/context/epoch-local. A rebuild advances the session epoch even if some realized shapes are reused. Persistent references are re-resolved; raw handles are not refreshed into durable identity.

## Scope and fail-closed cardinality

Source declarations require explicit scope:

```aicad
query hole_wall : Face in Wall.bored_a {
    generated_by(bored_a);
    cylindrical();
    unique();
}
```

Production lowering calls `Query::scoped_to(FeatureAnchor)`. If scope cannot be resolved, the result is broken rather than a silent fallback to the broad whole-session candidate set.

Cardinality yields:

- zero/too few matching candidates -> `Broken`;
- exactly the expected count -> `Resolved`;
- too many matching candidates -> `Ambiguous`.

Ranking may narrow a candidate set according to authored semantics, but genuine equal candidates are not arbitrarily ordered into one winner.

## Feature/provenance and lineage

`FeatureGraph` owns AICAD feature identity and source scope/provenance. The incremental dispatcher captures kernel lineage for supported topology-changing operations; `reference_replay` classifies it into resolver-consumable evidence. Feature lineage is indexed per entity kind so Face and Edge evidence remain distinct.

This evidence is refreshed as real geometry is regenerated by `ParametricBuildSession::rebuild`.

## Source references and health

`ParametricBuildSession::source_references()` exposes the program's real lowered references. `cad refs check` calls the production health checker against that set. A source file with no queries has an honestly empty set.

## Fingerprint policy

Fingerprint evidence is non-authoritative. Automatic fingerprint recovery remains disabled by D7: a `GeometricFingerprint` construction strategy does not silently resolve from similarity. Any future change to that policy requires an explicit owner decision.

## Stage-5 boundary

The remaining source-vocabulary gaps, richer spatial/dimensional operands, and Stage-5 advanced geometry are planned work. Do not implement them by widening Stage-4 resolver semantics or leaking OCCT-specific types upward.
